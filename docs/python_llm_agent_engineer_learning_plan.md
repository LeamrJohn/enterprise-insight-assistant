# Python / LLM / Agent 工程师学习计划

## 目标

在约 12 周内，以当前仓库为主要教材和练习场，建立初级偏中级 Python 工程师的基础能力：

- 独立完成普通 Python 后端模块，并能编写测试与文档。
- 理解并使用 FastAPI、PostgreSQL、Redis、Celery、Docker、日志与基础监控。
- 完成一个可控的 LLM / RAG / Agent MVP，而不是只做聊天页面或堆叠框架。
- 能结合真实项目经历回答初级到初中级后端、LLM 和 Agent 岗位的高频问题。

建议每周投入 15～20 小时；若每周投入 8～10 小时，按相同顺序拉长周期。

## 总体原则

1. 现有项目是参考实现和练习场，不把它当作不可质疑的标准答案。
2. 不通读所有源码；只沿着一个完整功能链路学习和实践。
3. 每个知识点必须落到代码、测试、运行验证和复盘上。
4. 先掌握可交付的基础能力，再深入复杂的多 Agent、评测和生产架构。
5. 面试准备基于已完成的项目实践，不以背诵孤立答案为主。

## 现有项目中的学习主线

```text
请求 → API 路由 → Service → Repository → 数据库 → 响应 → 测试
```

第一条主线使用现有 `documents` 模块；后续由学习者独立完成 `tasks`（待办/工单）模块，再依次引入异步任务、LLM、RAG、工作流和部署能力。

## 阶段安排

### 第 0 阶段：熟悉项目与学习方式（2～3 天）

目标：理解一个功能从请求到测试的完整链路。

学习内容：

- `app/main.py` 的应用启动、中间件、异常处理器和路由注册。
- `documents` 模块中的 API、Service、Repository、Model、Schema 和测试。
- 404、409、422、500 的基本语义。

验收：不看代码，能画出文档模块调用链，并解释每层职责。

### 第 1 阶段：Python 与工程基础（第 1～2 周）

目标：能稳定编写、测试和维护服务端 Python 代码。

学习内容：

- 函数、模块、包、导入机制、常用容器、迭代器和生成器。
- 类型标注、Pydantic 模型、基础类与协议。
- 异常边界、文件处理、环境变量、虚拟环境和依赖声明。
- `pytest` fixture、mock、参数化测试、Ruff 和 Git 基础。

实践：补充一个纯 Python 的校验或文本处理函数及其测试；每次修改前后运行测试和静态检查。

高频面试主题：可变默认参数、深浅拷贝、装饰器、生成器、上下文管理器、异常处理、虚拟环境、单元测试与集成测试。

### 第 2 阶段：FastAPI、数据库与标准模块交付（第 3～5 周）

目标：独立完成 `tasks` 模块。

功能范围：

- 任务创建、列表、详情、更新和删除。
- 标题、描述、状态、优先级、截止时间、创建时间等字段。
- 用户隔离、输入校验、404 / 422 响应。
- Alembic 迁移、Swagger 调试和至少 8 条测试。

需要形成的工程判断：

- Schema 负责格式和基础约束；Service 负责业务规则。
- Repository 只负责数据读写；业务层不直接拼 SQL。
- 可预期业务错误转换为明确响应；无法恢复的异常记录上下文后继续抛出。
- 日志记录请求 ID、资源 ID、操作、耗时和异常，但不记录密钥或敏感正文。

高频面试主题：依赖注入、Pydantic 与 ORM 分工、HTTP 状态码、事务、SQL 注入、索引、N+1、Alembic。

验收：不查看 `documents` 的具体实现，能独立完成 `tasks` 的核心代码和测试。

### 第 3 阶段：异步、缓存、Docker 与可观测性（第 6～7 周）

目标：让 `tasks` 模块具备基本真实系统能力。

实践：

- 添加一个长耗时动作，例如文件导入或任务摘要生成。
- 使用 Celery + Redis 执行异步任务，保存 pending / running / succeeded / failed 状态。
- 练习超时、重试和幂等性。
- 使用 Docker Compose 启动 API、PostgreSQL 和 Redis。
- 使用结构化日志、请求 ID、健康检查；为一个查询增加基础缓存。

高频面试主题：同步/异步/并发/并行、`async/await`、Broker 与 Backend、任务可靠性、缓存常见问题、Docker 与 Compose、日志/指标/链路追踪。

验收：他人可按 README 启动项目；能解释异步任务从 API 到 Worker 再到状态查询的链路。

### 第 4 阶段：LLM 应用基础（第 8 周）

目标：完成一次安全、可测试的结构化 LLM 调用。

实践：实现“根据工单描述提取问题类型、优先级和建议操作”的能力。

- 使用 Prompt 模板和 Pydantic 结构化输出。
- 对不合规模型响应进行失败处理或有限重试。
- 记录 token、延迟、模型名称和调用结果。
- 不将模型文本直接作为数据库操作或危险工具参数。
- 测试中 mock 模型调用。

高频面试主题：Prompt 角色、结构化输出、tool calling、上下文、token/延迟/成本、温度参数、模型输出校验。

### 第 5 阶段：RAG（第 9～10 周）

目标：完成可解释的带引用文档问答。

学习与实践：

- 文档解析、切分、Embedding、向量检索、top-k、重排、引用溯源。
- 回答必须附带来源文档和片段；证据不足时明确拒答。
- 准备 20～30 条问题组成小型评测集。
- 判断何时不应使用 RAG：纯计算、稳定通用知识、严格事务操作等。

高频面试主题：RAG 与微调、切分策略、向量相似度局限、幻觉控制、检索与回答评测、权限隔离。

### 第 6 阶段：受控 Agent 与工作流（第 11 周）

目标：将现有 LangGraph 能力收敛为稳定、可解释的工作流。

场景：根据用户问题检索知识库，必要时查询任务/工单数据，输出带证据的建议；涉及修改操作时等待人工确认。

工作流控制在 4～5 个节点：

```text
输入校验 → 意图判断 → 检索或查询受控工具 → 结果校验与汇总 → 输出或人工确认
```

必须掌握：状态机、工具白名单、参数校验、超时、重试、幂等性、人工介入和失败降级。

高频面试主题：Agent/Workflow/Chatbot 区别、企业中工作流优先的原因、提示词注入、长任务与状态持久化。

### 第 7 阶段：上线、评测与面试收口（第 12 周）

目标：把项目收敛成可运行、可演示、可说明边界的 MVP。

交付内容：

- Docker Compose 一键启动、完整 `.env.example` 和 README。
- 健康检查、结构化日志、基础指标。
- RAG / Agent 评测集与结果记录。
- 用户隔离、敏感数据脱敏、限流、工具白名单和审计日志。
- 明确项目限制，以及哪些操作不交由 Agent 执行。

围绕项目准备 10 个面试故事：模块设计、测试排错、技术选型、事务、模型输出控制、RAG 改进、工作流收敛、安全、评测、线上故障排查。

## 每次学习的执行节奏

每次学习约 2～3 小时：

```text
20 分钟：理解一个概念和现有相关代码
30 分钟：写输入、输出、异常、分层和测试场景
60～90 分钟：独立编码
20 分钟：运行测试、静态检查和观察日志
10 分钟：记录设计判断与复盘
```

## 协作方式

1. 教练给出贴近当前项目的小需求与验收标准。
2. 学习者先说明输入、输出、异常、分层和测试场景。
3. 先审查设计判断，再开始编码。
4. 遇到困难时优先提供最小提示，而不是完整答案。
5. 完成后进行代码审查，并将实现过程转化为可用于面试表达的项目经验。
