## 现状与调用链

`backend/pyproject.toml` 定义开发依赖；Docker 使用 `requirements/base.txt`，后者还包含附件处理依赖，因此干净测试环境需要安装两者。Python 3.12 与 Docker/Pyright 对齐，仅作为本轮验证版本，不据此宣称其他版本已通过。

`tests/conftest.py::migrated_test_database` → Alembic `upgrade head`（`agent_migrator`）→ `db_session`（`agent_app`、外层事务和 savepoint）→ 测试 → 回滚。复用 `scripts/db/bootstrap_postgres.sql` 创建角色、数据库和 vector 扩展，不用超级用户执行应用测试。单元目录中的测试也可能使用数据库，不能按目录名称假定没有真实依赖。

## 12 项设计

| 项 | 本模块的实现约束 |
|---|---|
| 1 职责 | 自动执行原计划要求的 Ruff、Pyright、单元/脚本、真实 PostgreSQL 集成检查；前端与 Compose 检查补充工程基线。不上线、不发布。 |
| 2 生命周期 | 配置随 Git 保存；每个运行使用独立服务容器；测试报告作为运行产物保存 14 天，原始运行日志按平台策略保存；不新增业务表。 |
| 3 契约 | 输入为 PR/push 的代码与配置；输出为各 job 状态和测试报告。非零退出码传播；缺少必需检查不能算通过。 |
| 4 状态 | 平台管理排队、执行与终态；重跑是新尝试，不覆盖旧日志。取消不是通过。 |
| 5 权限 | workflow 仅读仓库内容，checkout 不保留凭据；只使用服务容器的公开测试口令，不注入业务密钥。 |
| 6 失败 | 安装、初始化、迁移、测试和报告上传分别失败；不使用 continue-on-error 或伪造成功；保留失败输出，不无限重试。 |
| 7 资源 | 每个 job 设置超时；同一 PR/ref 的新运行可取消旧检查，不同运行的服务容器隔离；具体耗时需首轮实测后调整。 |
| 8 一致性 | 前端 npm ci 复用已提交锁；后端 CI 使用 Linux/Python 3.12 哈希锁，再离线验证项目依赖声明并执行 pip check。ML Worker、Windows、系统镜像不在此锁的证明范围。 |
| 9 可观测 | 平台记录 commit/run/attempt、步骤、时间和退出码；保存 JUnit；不上传 .env、数据库转储或整份运行目录。 |
| 10 测试 | 分开运行 unit/scripts 和 integration，显式排除 e2e/slow；真实 PG/Redis 服务不等于完整 Worker E2E。至少完成失败传播和初始化失败两项演练。 |
| 11 运维 | CI/pre-commit 配置可按提交回退；失败的门禁不删除以制造全绿。远端必需检查与 PR 审查规则需要实际配置、验证。 |
| 12 安全 | 用 pull_request 而非带高权限的 pull_request_target 执行 PR 内容；服务仅供该 job 使用；应用账号不得绕过 RLS。 |

## 本轮切片与验证

先建立 CI 骨架及缺失的开发工具声明，复用现有初始化 SQL、迁移、测试命令。静态检查作为真实失败门禁，存量错误另行逐项修复，不因错误多而自动降标。Ruff 0.16.1、Pyright 1.1.414 固定为本轮实测工具版本，避免门禁规则随安装日期改变；工作流 Actions 固定到经远端查询确认的提交 SHA。pre-commit、测试分层完善和 PR 故障演练仍按阶段 1 顺序推进。

验证：工作流语法与依赖声明检查；前端测试/构建；Ruff/Pyright 当前结果；独立数据库上的迁移和后端测试；最后以实际 GitHub PR run 验证服务容器、检查与报告上传。已有本地结果不能代替远端 run。
